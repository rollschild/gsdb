# gsdb bug audit (2026-10-05)

Full read of `src/`, `include/libgsdb/`, `tools/gsdb.cpp`, `test/` at commit `82fec92`.
Report only: no source files were changed.
Line numbers were re-synced on 2026-10-10 against `74d1d4b`. Fixed findings are marked **Status: fixed**.

## How this was checked

- **Build and tests:** a clean scratch build compiles with no warnings, and all 37 tests (231 assertions) pass.
- **Sanitizers:** a second scratch build of libgsdb, the CLI and the tests used `-fsanitize=address,undefined`. The test targets were copied in from the plain build so they stay uninstrumented. The suite still passes, but ASan reports **C1** on every run.
- **Reproductions:** findings marked **✔ reproduced** were triggered with the CLI (plain or ASan build) or a small harness linked against `libgsdb.a`. The commands are in the Evidence lines. Findings marked **◇ code reading** were not reproduced.
- **Comparison with sdb:** findings tagged `[sdb]` are also in TartanLlama/sdb `main`, so they come from the reference code. `[gsdb-only]` marks places where the port diverges from sdb. Untagged findings were not compared.
- **No bugs found in:** `registers.cpp`, `stoppoint_collection.hpp`, `disassembler.cpp`, `syscalls.cpp`, `pipe.cpp`.

Severity:

- **Critical:** memory-safety bugs, or a crash/hang in a normal workflow.
- **High:** wrong results, corruption of the inferior, or a headline feature broken in common use.
- **Medium:** wrong behaviour in plausible but narrower cases.
- **Low:** edge cases, malformed input, latent UB.

## Critical

### C1. Demangled symbol names dangle (heap use-after-free) `[sdb]`
- **Status:** fixed in `fd6be79`. `symbol_name_map_` now stores `std::string` keys (`include/libgsdb/elf.hpp:125-127`), so line 185 copies the demangled name before line 186 frees it.
- **Where:** `src/elf.cpp:183-186`.
- **Bug:** `symbol_name_map_` is keyed by `std::string_view`. The demangled name is inserted as a view into the buffer returned by `__cxa_demangle`, and that buffer is `free`d on the next line. libstdc++ caches each key's hash, so the freed bytes are read whenever a later insert or lookup has the same hash and compares keys (for example, constructor variants C1 and C2 both demangle to `Foo::Foo()`).
- **Evidence:** ASan reports heap-use-after-free in `build_symbol_maps` whenever an ELF with C++ symbols is loaded (libstdc++ via the rendezvous). The test suite hit it.
- **Fix:** keep the demangled strings alive in a member (`std::deque<std::string>`, which keeps references stable) and key the map with views into that. Or key the map with `std::string`.

### C2. CFI expressions point at a temporary `dwarf` `[sdb]`
- **Status:** fixed in `501504a`. All three sites pass `elf.get_dwarf()` (`src/dwarf.cpp:769-772, 818-821, 828-831`), and `dwarf(const elf&)` is now `explicit` (`include/libgsdb/dwarf.hpp:444`), so passing an `elf` no longer compiles.
- **Where:** `src/dwarf.cpp:769, 818, 828` (the three `gsdb::dwarf_expression{…}` constructions).
- **Bug:** `dwarf_expression` takes `const dwarf&`, but these sites pass `const elf&`. Because `dwarf(const elf&)` was an implicit converting constructor (`dwarf.hpp:444`), each call builds a temporary `dwarf`, which re-parses every CU and the `.eh_frame_hdr`. `parent_` then points at that dead temporary. `eval()` dereferences it immediately (`dwarf.cpp:1841`).
- **Evidence:** a function containing `asm(".cfi_escape 0x10,0x03,0x02,0x76,0x00")` (DW_CFA_expression), stopped at a breakpoint, gave ASan stack-use-after-return in `dwarf_expression::eval`, reached from `stack::unwind`.
- **Fix:** pass `elf.get_dwarf()`. Mark `dwarf(const elf&)` `explicit` so the compiler rejects this mistake in future.

### C3. `breakpoint delete` is a use-after-free `[sdb]`
- **Status:** fixed in `f003f79`. The CLI now saves the site addresses, calls `remove_by_id` while the sites are still alive, and only then removes the sites.
- **Where:** `tools/gsdb.cpp:556-564`.
- **Bug:** the CLI first destroys the process-owned `breakpoint_site` objects (`remove_by_address`). It then calls `breakpoints().remove_by_id()`, which calls `breakpoint::disable()` on the non-owning pointers to those freed sites.
- **Evidence:** `break set main` then `break delete 1` gave ASan heap-use-after-free in `breakpoint_site::disable`.
- **Fix:** add `target::remove_breakpoint(id)`. It should disable the breakpoint while its sites are alive, remove the sites from the process, then erase the breakpoint. Optionally give `breakpoint` a destructor that does the same.

### C4. Stack-frame accessors are unchecked `[sdb]`
- **Where:**
  - `include/libgsdb/stack.hpp:47-48, 56`
  - `src/stack.cpp:50-52`
  - `src/target.cpp:707`
  - callers in `tools/gsdb.cpp:359, 940, 972` and `src/target.cpp:99, 937`
- **Bug:** `current_frame()` and `regs()` index `frames_` without checking for emptiness. `frames_` is empty right after launch (stopped in ld.so) and whenever the PC is in code without DWARF. `up()` and `down()` are unbounded, and `down()` at 0 wraps to `SIZE_MAX`. `step_out` reads `frames()[idx + 1]` even from the outermost frame.
- **Evidence:**
  - `register read` as the first command segfaults (plain build dumps core).
  - `down` at frame 0 gives ASan heap-buffer-overflow in `print_code_location`.
  - `finish` in `main` prints `Enabling breakpoint site failed!: Input/output error` (garbage return address).
- **Fix:** have `unwind()` always produce frame 0 from the live registers, even when there is no DWARF. Bound-check `up`/`down` and report "no more frames". In `step_out`, error out if there is no caller frame.

### C5. Out-of-bounds reads and writes in variable/expression code
- **a. `setup_arguments` copies a fixed 8 bytes** (`src/target.cpp:363-368`) from `arg.data()`, whatever its size. A char literal holds 1 byte; `int` and `bool` variables hold 4 and 1. **✔ ASan:** `expression print_type('a')` gave heap-buffer-overflow in `setup_arguments`. `[sdb]`
  **Status:** fixed in `7719cd7`: the copy now takes at most `bytes.size() - i` bytes into a zeroed buffer.
  **Fix:** copy `min(8, size - i)` bytes into a zeroed `byte64`.
- **b. `typed_data::index` has no bounds check for arrays** (`src/type.cpp:514-515`). **✔ ASan:** `variable read arr[100]` gave heap-buffer-overflow.
  **Status:** fixed in `7719cd7`: `src/type.cpp:511-513` rejects an out-of-range index.
  **Fix:** error if `element_size == 0 or index >= data_.size() / element_size`. Dividing avoids the wrap-around that `index * element_size` hits for huge indexes.
- **c. `$N` lookup has no bounds check** (`src/target.cpp:1168`). **✔** `variable read $5` with no results gave SEGV.
  **Status:** fixed in `7719cd7`: `src/target.cpp:1165-1167` rejects an out-of-range index.
  **Fix:** check `i < expression_results_.size()`.
- **d. `read_location_data` pieces are mishandled** (`src/target.cpp:976-994`) `[sdb]`. The aligned branch copies the whole register value (8 or 16 bytes) for a smaller piece. If the last piece is smaller than its register, this writes past the end of `data`. The unaligned branch always writes at bit 0 and never advances `offset`. ◇ (needs optimized code)
  **Status:** fixed in `7719cd7`: the loop copies only the piece's bytes, writes bit pieces at `offset`, advances `offset` in both branches, and rejects pieces larger than the variable. A test program calling `read_location_data` under ASan confirmed it: a 12-byte variable split across `%rax` and `%rdx`, two bit pieces in one byte, and oversized pieces all behave correctly.
  **Fix:** copy exactly `byte_size` bytes. Use `memcpy_bits(dest, offset, …)` and `offset += piece.bit_size` in both branches.
- **e. Literal locations over-read** (`src/target.cpp:958-963`) `[sdb]`. `literal_result` copies `size` bytes from an 8-byte `uint64_t`, which over-reads the stack for types larger than 8 bytes. ◇
  **Status:** fixed in `7719cd7`: the branch copies at most 8 bytes into a zero-filled vector of exactly `size` bytes. A test program under ASan read `DW_OP_const8u 0x1122334455667788; DW_OP_stack_value` at sizes 4, 8 and 16 and got the low 4 bytes, the full value, and the value followed by 8 zero bytes.
  **Fix:** copy `min(size, 8)` and zero-fill the rest.

### C6. Watchpoint size >8 overflows the stack
- **Status:** fixed in `39fc5fe`. The constructor now rejects sizes other than 1, 2, 4 and 8, and `execute` watchpoints wider than 1 byte, before `update_data()` runs (`src/watchpoint.cpp:26-31`), and `update_data()` clamps the copy to 8 bytes (line 61). `watchpoint set 0x555555558040 write 16` now prints the size error and leaves no watchpoint behind. The two new messages misspell "watchpoint" ("Watchponit", "watchponits").
- **Where:** `src/watchpoint.cpp:26-36, 61`; `tools/gsdb.cpp:631-645`.
- **Bug:** the constructor calls `update_data()` before the size is validated. `memcpy(&new_data /* uint64_t */, …, size_)` therefore overflows for `size > 8`. Size validation only happens later, in `enable()`.
- **Evidence:** `watchpoint set 0x555555558040 write 16` gave ASan stack-buffer-overflow in `memcpy`.
- **Fix:** reject sizes other than 1, 2, 4 or 8 (and require `execute ⇒ 1`) at the top of the constructor. Validate in the CLI too.

### C7. An unwinder exception corrupts process state, then gsdb hangs on quit
- **Status:** fixed in `2fff049`.
  - Unwinding is best-effort: `stack::unwind` stops at the first frame it can't unwind (`src/stack.cpp:100-111`), and `target::notify_stop` swallows anything else (`src/target.cpp:536-542`).
  - If `handle_signal` still throws, `wait_on_signal` records the stop, stops the other threads, and only then rethrows (`src/process.cpp:439-451`).
  - `~process` no longer trusts `state_` (`src/process.cpp:134-183`). A launched inferior gets SIGKILL and every thread is reaped through its process group. For an attached one, `/proc` decides which threads still need stopping (`in_ptrace_stop`, line 122).
  - Launched inferiors get `PTRACE_O_EXITKILL` (`src/process.cpp:51-62`).
  - Checked on a scratch build of the working tree: the no-unwind-tables and non-PIE binaries now report the stop, `backtrace` shows frame 0, and gsdb exits in about 65 ms. A throwing breakpoint hit handler leaves the process and thread recorded as stopped, and `continue` works afterwards. `kill -9` on gsdb takes the inferior with it.
  - Still open nearby: if unwinding fails before frame 0 is built, the frame list stays empty and C4 applies.
- **Where:**
  - `src/process.cpp:350-353` (`notify_stop` runs inside `handle_signal`)
  - `src/process.cpp:134-183`
  - `src/target.cpp:536-542`
- **Bug:** if `stack::unwind()` throws, the exception leaves `wait_on_signal` part-way through. Thread state is never updated, `stop_running_threads` never runs, and `state_` stays `running` even though the tracee is stopped. Several things make unwinding throw: no FDE, the CIE `S` augmentation (M4), `.at()` in the CFI code (M2), or an undefined register. On quit, `~process` then sees `running`, sends SIGSTOP and blocks forever in `waitpid` on a tracee that is already ptrace-stopped. If gsdb is killed instead, the inferior is left orphaned and stopped.
- **Evidence:**
  - With a callee built with `-fno-asynchronous-unwind-tables`, `c` printed `No unwind information at PC!` instead of a stop report. EOF then hung in `~process` (gdb backtrace: `wait4 ← process::~process`).
  - A non-PIE build showed the same thing (see M5).
- **Fix:**
  - Catch in `target::notify_stop` (or `stack::unwind`) and keep the frames unwound so far.
  - In `~process`, skip the SIGSTOP/`waitpid` when the threads are already stopped, or use `WNOHANG`.
  - Add `PTRACE_O_EXITKILL` for launched processes so a crashing gsdb never leaves the inferior behind.

### C8. Any non-`gsdb::error` exception aborts the debugger `[sdb]`
- **Where:** `tools/gsdb.cpp:1121` (and `main`, 1161).
- **Bug:** only `gsdb::error` is caught, so `std::out_of_range`, `bad_optional_access`, `bad_variant_access`, `length_error` and similar call `std::terminate`. The inferior is then orphaned.
- **Evidence:**
  - After the program exits, any stack command (`register read`, `backtrace`, `variable …`) gives `std::out_of_range`. `target::notify_thread_lifecycle_event` erased the main thread (`target.cpp:922`).
  - `catchpoint syscall 1x` gives `bad_optional_access` (`gsdb.cpp:875`).
  - `thread select 4242` followed by any command gives `out_of_range`. The TID is never validated (`gsdb.cpp:922`).
  - `memory write <addr> [0xzz]` gives `bad_optional_access` (`include/libgsdb/parse.hpp:102`).
- **Fix:** also catch `std::exception` in `main_loop` and print `what()`. Validate `thread select` against `thread_states()`. Replace `.value()` in the parsers with explicit checks. Have commands refuse with "process has exited" once the process is gone.

### C9. Unbounded recursion in `wait_on_signal` `[sdb]`
- **Where:** `src/process.cpp:455, 471`.
- **Bug:** every swallowed event recurses: a filtered syscall entry or exit, a clone event, an auto-restarting breakpoint, or a thread exit. At `-O1` there is no tail-call optimisation.
- **Evidence:** `catchpoint syscall write` on a program doing N `getppid()` calls: N=2000 works, N=20000 gives SIGSEGV (stack overflow).
- **Fix:** turn the body into `while (true) { … continue; }`.

### C10. Binaries without `.eh_frame_hdr` or `.dynamic` crash gsdb `[sdb]`
- **Where:** `src/dwarf.cpp:365-386` (`parse_eh_hdr`); `src/target.cpp:797-800`.
- **Bug:** `parse_eh_hdr` dereferences empty optionals and reads through a `{nullptr, 0}` span. Static links get no `--eh-frame-hdr` from the GCC driver. `resolve_dynamic_linker_rendezvous` calls `.value()` on a missing `.dynamic`, inside the entry-point hit handler.
- **Evidence:** `gcc -static -nostdlib` program: gsdb segfaults during launch.
- **Fix:** make CFI optional (an empty table, or fall back to a linear `.eh_frame` scan). Return early when there is no `.dynamic`.

### C11. `resolve_indirect_name` hangs and has UB
- **Status:** fixed in `8f20ddf`. Both `name[op_pos]` reads check `op_pos != std::string::npos` first (`src/target.cpp:1027, 1052`). A missing `]` throws `Invalid []!` (line 1075), any other character throws `Unexpected '…' in variable name!` (lines 1084-1087), and the closing `find_first_of(".-[(")` no longer contains `,` (line 1088). A 20,000-name fuzz run found no hang and no out-of-range read. Text after the last member is still silently ignored: `me.pets,x` reads `me.pets`.
- **Where:** `src/target.cpp:1027, 1052, 1072-1088`.
- **Bug:**
  1. `[gsdb-only]` The end-of-loop `find_first_of(".-[(,")` includes `,`, so any `,` loops forever. This was already noted on 2026-09-22 and is still unfixed.
  2. `name[op_pos]` is evaluated when `op_pos == npos` (a plain name, or a member at the end of the name), which is out-of-range `operator[]` (UB).
  3. A missing `]` makes `int_end + 1` wrap to 0. The whole name is then re-parsed and indexed repeatedly.
- **Evidence:** `variable read me.pets,x` hangs (killed by `timeout`, rc 124). `variable read cats[1` prints the misleading `Not an array or pointer type!`.
- **Fix:** drop `,` from line 1088. Test `op_pos != npos` before indexing. Error on a missing `]`.

### C12. SIGFPE when classifying a struct with a typedef'd struct member
- **Status:** fixed in `74d1d4b`. `alignment()` strips cv and typedef and starts `max_alignment` at 1 (`src/type.cpp:745-751`). `has_unaligned_fields()` iterates the stripped type and skips `align == 0` (lines 778, 785-786). `expression take_w(w)` no longer crashes, but it returns `140737488309817` instead of `15`, because classification still reads unstripped DIEs (H11b).
- **Where:** `src/type.cpp:740-770` (`alignment`), `772-798` (`has_unaligned_fields`).
- **Bug:** `alignment()` checks `is_class_type()`, which strips cv and typedef, but then iterates the children of the **unstripped** DIE. A typedef or `const` DIE has no children, so `max_alignment` is 0. `has_unaligned_fields()` then computes `offset % 0`. An empty struct gives the same result.
- **Evidence:** `struct W { TS t; }` where `TS` is a typedef'd struct: `expression take_w(w)` kills gsdb with SIGFPE (exit 136).
- **Fix:** strip cv and typedef at the top of `alignment()` and `has_unaligned_fields()`, and treat alignment 0 as 1. This is the same root cause as H11b.


### C13. Quitting with a multi-threaded inferior hangs gsdb
- **Status:** fixed in `2fff049`, by the same destructor rewrite as C7. A launched inferior gets SIGKILL, then `waitpid(-pid_, …, __WALL)` reaps every thread in its process group, main thread last (`src/process.cpp:147-161`). The attach path detaches every thread, not just `pid_` (lines 163-182).
- **Where:** `~process`, `src/process.cpp:134-183`.
- **Bug:** the old destructor detached only the main thread, then sent SIGKILL and waited for `pid_` alone. The other threads were still traced by gsdb, and a killed thread that is still traced stays a zombie until its tracer reaps it. The kernel reports the main thread's exit only after every other thread is gone, so `waitpid(pid_)` never returned. Found on 2026-10-08 while working on C7.
- **Evidence:** a test program launched a 3-thread program, stopped it cleanly and destroyed the `process`. gdb showed it stuck in `wait4` on the old destructor's `waitpid(pid_, …)` line. The same happened with the threads still running. With the new destructor both cases return.
- **Fix:** after SIGKILL, reap every thread through the inferior's process group, which also covers threads gsdb hasn't registered yet, until `waitpid` reports `ECHILD`. On the attach path, detach each thread.

## High

### H1. Inferior calls overwrite the red zone and misalign the stack
- **Where:**
  - `src/process.cpp:1035-1042`
  - `src/target.cpp:181-194, 282, 316-317, 377, 1094-1127`
- **Bug:** every stack write starts at the current `%rsp`: the return-address push, stack arguments, reference temporaries, the object spill, and `malloc`'s frame. SysV leaf functions keep locals in the 128-byte red zone below `%rsp`, so those locals get overwritten. `inferior_malloc` also never aligns `%rsp`, so `malloc` can be entered misaligned.
- **Evidence:** in a `-O0` leaf, `expression id(5)` changed local `x` from 42 to 140737488309488 and `a` from 21 to 5. The program then printed `leaf=281474976618977` instead of 85.
- **Fix:** in one helper used by every inferior call, first do `rsp -= 128`. Then lay out the arguments, align to 16, and push the return address, so that `%rsp ≡ 8 (mod 16)` at entry.

### H2. Signals are never delivered to the inferior
- **Where:** `src/process.cpp:242` (and the single-steps at 221 and 672).
- **Bug:** every restart passes signal 0. That suppresses whatever signal caused the stop: SIGUSR1/SIGALRM/SIGCHLD/SIGPIPE handlers never run, SIGTERM is swallowed, and SIGSEGV re-faults forever.
- **Evidence:** a program that `raise(SIGUSR1)`s with a handler prints `handler ran` natively. Under gsdb, `c` and `c` again print only `main done`.
- **Fix:** record the pending signal per thread on signal-delivery stops (not SIGTRAP, and not SIGSTOPs gsdb injected). Pass it as the `data` argument of `PTRACE_CONT`/`SINGLESTEP`, then clear it.

### H3. Detaching leaves `int3` bytes in the attached process
- **Status:** partly fixed in `2fff049`. Before detaching, `~process` now disables every breakpoint site and watchpoint, then detaches every thread (`src/process.cpp:163-182`). Still open: a thread stopped on an `int3` that gsdb never processed is detached with `%rip` one byte past the breakpoint. Rewind it first: the stop is a SIGTRAP with `si_code == SI_KERNEL`, and `%rip - 1` is an enabled software site.
- **Where:** `src/process.cpp:134-183`; `src/target.cpp:827-834`.
- **Bug:** `~process` sends `PTRACE_DETACH` without disabling breakpoint sites. `target::attach` always enables an internal breakpoint on `_dl_debug_state`. After gsdb quits, the next `dlopen`/`dlclose` (or any surviving user breakpoint) delivers SIGTRAP and kills the process.
- **Evidence:** a test program attached to a process, stopped it at a software breakpoint in a hot loop, and destroyed the `process`. With the old destructor the detached process was killed by the leftover `int3` (state `Z`). With the working-tree destructor it keeps running (state `R`).
- **Fix:** before detaching, disable every software site and clear DR7 on every thread.

### H4. Attaching to a multi-threaded process cannot resume
- **Where:** `src/process.cpp:571, 998-1005`.
- **Bug:** only the TGID is `PTRACE_ATTACH`ed. The other TIDs from `/proc/<pid>/task` are tracked but not traced, so `resume_all_threads` fails on them. Their `stop_reason` is also uninitialized (L4).
- **Evidence:** a harness that launches a 3-thread program untraced, then calls `process::attach` and `resume_all_threads`, throws `Could NOT resume: No such process`.
- **Fix:** `PTRACE_ATTACH` and `waitpid` every TID, re-scanning `/proc/<pid>/task` until no new TIDs appear. Then set the ptrace options on each one.

### H5. `next`/`finish` run away past a disabled breakpoint
- **Where:** `src/target.cpp:618-622`.
- **Bug:** `run_until_address` only plants a temporary site if none exists. If a user site exists at that address but is **disabled**, nothing traps.
- **Evidence:** `break set 0x55555555517c` (main's return address after the first call), then `break disable 2`, then `next` over the call. The program ran to completion, and then gsdb aborted with `out_of_range` (H6).
- **Fix:** if the existing site is disabled, enable it temporarily and restore its state afterwards.

### H6. Stepping past program exit errors or aborts
- **Where:** `src/target.cpp:631-636`; `src/process.cpp:678-680`.
- **Bug:** after an exit, `run_until_address` calls `remove_by_address`, whose `disable` issues `PTRACE_PEEKDATA` on a dead PID. It also writes `threads_.at(tid)` for a thread that has already been erased. `step_instruction` re-enables its site the same way.
- **Evidence:** `next` past the end of `main` prints `Thread … exited` then `Disabling breakpoint site failed!: No such process`. With no temporary site, it hits `std::out_of_range`.
- **Fix:** when `reason` is exited or terminated, drop the site object without touching memory and skip the thread-state writes.

### H7. Stop message prints the wrong breakpoint ID `[sdb]`
- **Where:** `tools/gsdb.cpp:244-246`; `include/libgsdb/breakpoint.hpp:97`.
- **Bug:** the message prints the **site** ID, and site IDs restart at 1 for every breakpoint. As a result every breakpoint reports `(breakpoint 1)`. Process-level site IDs also collide, so `breakpoint_sites().get_by_id` is ambiguous.
- **Evidence:** with breakpoint 1 disabled and breakpoint 2 on `find_happiness`, the stop says `(breakpoint 1)`. It also throws if the program executes its own `int3` (there is no site).
- **Fix:** expose the parent and print `parent->id()` plus `.site_id`. Handle "no site" gracefully.

### H8. Two breakpoints cannot share an address
- **Where:** `src/process.cpp:650-653`.
- **Bug:** `create_breakpoint_site` throws if any site already exists at the address. Setting `break set main` twice fails, and so does `break set main` followed by the `file:line` of main's first line. It also fails when the address matches the internal entry breakpoint.
- **Evidence:** `Breakpoint site already created at address 93824992235895`. The address is also printed in decimal.
- **Fix:** let a site carry a list of parents (reference-counted), and have `resolve()` reuse an existing site.

### H9. Variable commands ignore the selected frame
- **Where:** `tools/gsdb.cpp:927, 955, 964`; `src/target.cpp:1133`.
- **Bug:** scope lookup uses the innermost PC (`get_pc_file_address()`), while locations are evaluated with the selected frame's registers.
- **Evidence:** stopped in `callee`, after `up` into `main`: `variable read m` prints `Variable not found!`, and `variable read x` (callee's local) prints `7`, a garbage value.
- **Fix:** derive the PC from `get_stack().current_frame()`. Use `rip - 1` for frames above 0, as `stack::unwind` already does.

### H10. `register write` is not visible to `register read` `[sdb]`
- **Where:** `tools/gsdb.cpp:430` (writes the process registers); `tools/gsdb.cpp:359` (reads the frame's copy).
- **Evidence:** `register write rax 0x1234` followed by `register read rax` shows the old value.
- **Fix:** re-unwind (`get_stack().unwind()`) after a write. Alternatively, read frame 0 from `process.get_registers()`.

### H11. Inferior-call ABI bugs
- **a. The NTFPOC test is inverted** (`src/type.cpp:718, 724`) `[sdb]`. `(!x) != DW_DEFAULTED_in_class` treats `= default` copy constructors and destructors as non-trivial. **✔** `expression take_d(d)` → `NTFPOC types are not supported!`.
  **Fix:** `child[DW_AT_defaulted].as_int() != DW_DEFAULTED_in_class`.
- **b. Classification runs on unstripped types** (`src/type.cpp:226, 275, 654, 716`) `[sdb]`. `alignment` and `has_unaligned_fields` were fixed with C12 (`74d1d4b`). Still unstripped: `classify_class_field` iterates `field_type.get_die().children()` (line 226), `get_parameter_classes` passes `*this` to `classify_class_type` (line 654), which iterates `type.get_die().children()` (line 275), and `is_non_trivial_for_calls` passes `*this` to `is_copy_or_move_constructor` (line 716). `const S` and typedef'd struct parameters come out as NO_CLASS and are pushed on the stack instead of in registers. **✔** `take_cp(const P)` returned `140737488309817` instead of `11`.
  **Fix:** strip cv and typedef first, in `classify_class_field`, `classify_class_type` and `is_non_trivial_for_calls` (`alignment` and `has_unaligned_fields` are done).
- **c. SSE return eightbytes overwrite instead of append** (`src/target.cpp:433-435`) `[sdb]`. **✔** `{double, double}` came back as `{2.5, 0}`, and `{long, double}` came back as garbage. The stray `write_memory` inside the loop also writes 16 bytes into the return slot.
  **Fix:** append the low 8 bytes of `xmm0`/`xmm1`, and write the slot once.
- **d. Literals are not converted to the parameter type.** A `double` literal passed to a `float` parameter is passed as double bits (**✔** `half(3.0)` → `0`). An `int` variable passed to a `long` parameter over-reads (C5a).
  **Fix:** convert builtin literals to the DWARF parameter type (size, and float vs. double) before placing them. Reject mismatches.
- **e. Enums get NO_CLASS** (`src/type.cpp:617-655`), as do member pointers and `__int128`, so they are silently passed on the stack.
  **Fix:** classify `DW_TAG_enumeration_type` as INTEGER, using its underlying type.
- **f. Bitfield eightbyte index ignores the storage unit's byte offset** (`src/type.cpp:218-221`). A bitfield in bytes 8–15 is classified into eightbyte 0.
  **Fix:** add `data_member_location * 8`, or use the full `data_bit_offset`.
- **g. `type::operator==` compares only names after `strip_all`** (`src/type.cpp:573-583`). As a result `int == int*` and `S == S**`, and anonymous types never match. **✔** `take_ts(ts)` → `No matching function!`.
  **Fix:** compare tag by tag (pointer depth, cv qualifiers). Fall back to DIE identity for unnamed types.
- **h. `inferior_call` never checks where it stopped** (`src/process.cpp:1048-1055`). A breakpoint or signal inside the callee is treated as the return: registers are restored and a garbage result is reported.
  **Fix:** require `is_breakpoint() && pc == return_addr`. Otherwise restore the registers and report the error.
- **i. The object spill commits `%rsp` before `saved_regs` is snapshotted** (`src/target.cpp:181-191` vs `450`), so the inferior's `%rsp` stays shifted after the call.
  **Fix:** snapshot the registers once, at the start of `evaluate_expression`, and restore from that snapshot.
- **j. Expressions fail on attached processes** (`src/target.cpp:1117, 1147`) `[sdb]`. They look up the entry-point breakpoint, which only `launch()` creates, so they fail with `Stoppoint with given address not found!`.
  **Fix:** create the internal entry or return breakpoint in `attach()` too.
- **k. Arguments are not trimmed** (`src/target.cpp:213`). In `f(1, 2)`, `" 2"` is looked up as a variable.
  **Fix:** trim whitespace around each argument.

### H12. Functions containing a `goto` label break variable lookup `[sdb]`
- **Where:** `src/dwarf.cpp:1330-1334`.
- **Bug:** `contains_address` calls `high_pc()` on any DIE that has `DW_AT_low_pc`. `DW_TAG_label` has `low_pc` but no `high_pc`, so `scopes_at_address` throws.
- **Evidence:** in a `main` containing `done:`, `variable read x` and `variable locals` both print `DIE does not have high PC!`.
- **Fix:** require both `low_pc` and `high_pc`; otherwise return false.

## Medium

- **M1. `DW_CFA_expression` and `DW_CFA_val_expression` are swapped** `[gsdb-only]` (`src/dwarf.cpp:822, 832`). sdb maps them correctly. Registers saved through expression rules restore the address instead of the value, and vice versa. Producers of these rules include glibc's `__restore_rt` and GCC's DRAP realignment.
  **Fix:** swap the two `emplace` calls back.
- **M2. CFI rules never overwrite, and restore throws** `[sdb]` (`src/dwarf.cpp:715-722, 777-837`). `register_rules.emplace` ignores re-definitions. `DW_CFA_restore`/`restore_extended` use `.at()`, which throws an uncaught `std::out_of_range` when the CIE had no rule (C8).
  **Fix:** use `insert_or_assign`. For restore: assign the CIE rule if one exists, otherwise `erase`.
- **M3. Unknown CFA opcodes are skipped without consuming their operands** (`src/dwarf.cpp:726-852`, no `default`). For example `DW_CFA_GNU_args_size` (0x2e) leaves its ULEB operand to be parsed as an opcode.
  **Fix:** handle 0x2e by skipping its ULEB, and add `default: error::send(...)`.
- **M4. CIE augmentation letters other than z/R/L/P are rejected** (`src/dwarf.cpp:300-318`). glibc's signal trampoline CIE is `"zRS"`, so unwinding through signal frames throws.
  **Fix:** accept `S`, `B` and `G` (they carry no data), and use the `z` length to skip unknown augmentation data.
- **M5. CFI pointer decoding uses file offsets where it needs addresses** (`src/dwarf.cpp:344-352, 728-733, 1728-1757`). PC-relative and data-relative bases are computed from **file offsets**. This only works while `sh_addr == sh_offset`, as in a GNU-ld PIE. **✔** A `-no-pie` build gives `No unwind information at PC!`, and backtraces stop at frame 0.
  **Fix:** base = `section.sh_addr + (ptr - section_start)`. Convert FDE addresses back to offsets through the section headers.
- **M6. Printing `void*` fails** `[sdb]` (`src/type.cpp:41`, and `strip()` at `type.hpp:59`). **✔** `variable read vp` → `Attribute not found!`. `const void*` also throws.
  **Fix:** if the pointee has no `DW_AT_type`, print hex; stop stripping when `DW_AT_type` is absent.
- **M7. Hardware breakpoints and watchpoints don't reach threads created later** (`src/process.cpp:304, 825-830`). The kernel does not copy ptrace debug registers into new threads.
  **Fix:** when a new thread is registered, write DR0–3 and DR7 to it.
- **M8. The firing debug-register slot is mapped back by address, breakpoints first** `[sdb]` (`src/process.cpp:951-959`). A watchpoint on an address that also has a software site (the `anti_debugger` flow) is reported as a breakpoint, and its data is never refreshed.
  **Fix:** look up the owner of slot `index` through `hardware_register_index_`, considering only hardware stoppoints.
- **M9. `read_string` never advances `address`** `[sdb]` (`src/process.cpp:1007-1019`). A string longer than 1 KiB loops forever, growing memory.
  **Fix:** add `address += 1024` after the inner loop, and cap the total length.
- **M10. `expecting_syscall_exit_` is process-wide** (`include/libgsdb/process.hpp:309`). Entry/exit labelling gets mixed up across threads.
  **Fix:** move it into `thread_state`.
- **M11. `reset_inline_height` uses the current thread's PC** `[sdb]` (`src/stack.cpp:31`), so non-current threads get the wrong inline height.
  **Fix:** call `get_pc_file_address(tid_)`.
- **M12. `get_section_containing_address(virt_addr)` includes non-`SHF_ALLOC` sections** (`src/elf.cpp:140-150`). Those sections have `sh_addr` 0, so addresses near the load bias (or near 0 in a non-PIE) are attributed to `.debug_*`. `elf_collection` can then pick the wrong ELF.
  **Fix:** skip sections without `SHF_ALLOC`, and skip `.tbss`.
- **M13. `gsdb <name-in-PATH>` fails** (`src/target.cpp:492-493`). `execlp` searches `PATH`, but the ELF is opened relative to the CWD.
  **Fix:** open `/proc/<pid>/exe`, as `attach` already does.
- **M14. One CU or line table that isn't DWARF4 rejects the whole ELF** (`src/dwarf.cpp:449, 550`). GCC ≥ 11 defaults to DWARF 5. **✔** A plain `g++ -g` binary gives `Only DWARF version 4 is supported!` at launch. A DWARF5 shared library would throw mid-run from the rendezvous handler.
  **Fix:** even without DWARF5 support, skip unsupported CUs with a warning instead of throwing.
- **M15. `step_instruction` over a `clone` turns into a continue** (`src/process.cpp:439-455`). A clone event returns `nullopt`, and `resume(tid)` then issues `PTRACE_CONT`. The same applies to `step_over_breakpoint` when a signal arrives during the step, because the `waitpid` status is ignored (`src/process.cpp:225-232`).
  **Fix:** when waiting for a step, re-issue `PTRACE_SINGLESTEP`. Route the step's wait status through `handle_signal`.
- **M16. Indexing a multi-dimensional array ignores the inner dimensions** (`src/type.cpp:491-521`). GCC describes `int m[3][4]` as one `DW_TAG_array_type` whose `DW_AT_type` is `int`, with two `DW_TAG_subrange_type` children. `typed_data::index()` steps by `sizeof(int)` and drops the remaining dimension, so `m[1]` returns `m[0][1]` and `m[1][2]` fails with `Not an array or pointer type!`. **✔** On `int m[3][4]`, `variable read m[1]` printed `1`. `variable read m` is correct, because `visualize_subrange` does handle dimensions.
  **Fix:** step by the element size times the product of the remaining dimensions, and return a value that still carries those dimensions. DWARF has no DIE for `int[4]`, so `typed_data` needs its own dimension list that both `index()` and `visualize` read.

## Low

**Process and CLI control**

- **L1.** The child calls `exit(-1)` after `fork` (`src/process.cpp:43`), which runs `atexit` handlers and flushes duplicated stdio buffers. **Fix:** `_exit(127)`.
- **L2.** `~process` still sends DETACH/SIGCONT/SIGKILL to a PID that has already been reaped (`src/process.cpp:134-183`), which risks hitting a reused PID. The SIGINT handler has the same problem (`tools/gsdb.cpp:56-59`). SIGINT at the prompt also queues a SIGSTOP that fires on the next `continue`. **Fix:** skip these when the process is exited, and ignore SIGINT unless the inferior is running.
  **Status:** partly fixed in `2fff049`: `~process` now returns early once the process has exited (`src/process.cpp:138-141`), so it no longer signals a reaped PID. The SIGINT handler problems remain.
- **L3.** `read_memory` silently zero-fills partial reads (`src/process.cpp:727-730`). **Fix:** compare the return value with `amount` and error out.
- **L4.** `stop_reason() = default` leaves `reason`, `info` and `tid` uninitialized (`include/libgsdb/process.hpp:53, 76-80`), so `thread list` can read garbage. **Fix:** add default member initializers.
- **L5.** `write_memory` ignores enabled `int3`s, so a later `disable()` restores a stale byte. It also reads 8 bytes past the end for the tail (`src/process.cpp:735-760`). **Fix:** update `saved_data_` for sites in the written range, and clamp the tail read.
- **L6.** `get_auxv` loops forever, or reads uninitialized data, on a stream failure (`src/process.cpp:990-993`). **Fix:** check the stream state on every read.

**ELF and DWARF parsing**

- **L7.** `parse_section_headers` truncates the ≥0xff00 section count to 16 bits (`auto n_headers = e_shnum`, `src/elf.cpp:72-75`) `[sdb]`. **Fix:** use `std::uint64_t`.
- **L8.** `get_string` always uses `.strtab` instead of the symbol table's `sh_link` (`src/elf.cpp:113-123`). There is no ELF magic or bounds validation. The constructor leaks the fd and mmap if it throws (`src/elf.cpp:23-61`). **Fix:** use `sh_link`, validate `e_ident`/sizes, and make the constructor exception-safe (RAII for the fd and mmap).
- **L9.** Line-table issues:
  - `DW_LNE_define_file` appends on every iteration and invalidates `file_entry` pointers (`src/dwarf.cpp:1573-1579, 1493`).
  - `opcode_base > 13` indexes past `expected_opcode_lens` (`src/dwarf.cpp:575-583`).
  - A CU without `DW_AT_stmt_list` leaves `line_table_` null, which `lines()` dereferences (`src/dwarf.cpp:542`, `include/libgsdb/dwarf.hpp:433`).
  - A missing `DW_AT_comp_dir` throws (`src/dwarf.cpp:586-587`).
  **Fix:** parse define_file once, bound-check the opcode table, return an empty table, and use `value_or("")`.
- **L10.** `eh_hdr::operator[]` with `count == 0` sets `high = SIZE_MAX` (`src/dwarf.cpp:1723`). **Fix:** return "not found" early.
- **L11.** `skip_form` lacks `DW_FORM_ref8` and `DW_FORM_ref_sig8`, although `as_reference` handles ref8 (`src/dwarf.cpp:135-196`). `uleb128`/`sleb128` shift past 63 bits on malformed input. **Fix:** add the forms and guard the shift.
- **L12.** `create_base_frame` reads `file_entry` (null) from an end iterator (the "FIXME", `src/stack.cpp:133-135`). `print_code_location` then dereferences it (`tools/gsdb.cpp:797`). **Fix:** use an optional source location, and print disassembly when there isn't one.

**Breakpoints and watchpoints**

- **L13.** `function_breakpoint::resolve` calls `++` on an end iterator, a null dereference, when `low_pc` has no line entry (`src/breakpoint.cpp:57-60`). ELF symbols with `st_value == 0` or that aren't `STT_FUNC` produce sites at address 0 or in data (`src/breakpoint.cpp:75-85`). **Fix:** check against `end()`, and filter out `SHN_UNDEF` and non-FUNC symbols.
- **L14.** The `-h` flag is ignored for function breakpoints (`tools/gsdb.cpp:517`) `[sdb]`. **Fix:** pass `hardware`.
- **L15.** A failed `enable()` leaves a zombie breakpoint, site or watchpoint in its collection (`tools/gsdb.cpp:505, 645`; `src/target.cpp:619-621`). **Fix:** enable before pushing, or roll back on throw.
- **L16.** `break set file:` makes `split()` return one element, and `data[1]` is then out of bounds (`tools/gsdb.cpp:508-510`). **Fix:** check `data.size() == 2`.
- **L17.** `step_over` can stop early under recursion: the temporary site at the return address can hit in a deeper frame (`src/target.cpp:663-672`). **Fix:** also compare the frame count or CFA.

**Input parsing**

- **L18.** `to_integral` and `to_float` ignore `from_chars`' `errc` (`include/libgsdb/parse.hpp:22-34, 52-60`). An empty string or `"0x"` parses as 0, so `break set 0x` targets address 0; an overflow also yields 0. **Fix:** require `ec == std::errc{}` and a non-empty input.
- **L19.** `parse_vector` reads past the end of short input (`include/libgsdb/parse.hpp:69-112`). **Fix:** check the remaining length before taking 4 characters.
- **L20.** `memory read` stores the byte count in an `int` (`tools/gsdb.cpp:700-704`), so huge values end in a `length_error` abort. **Fix:** use `std::size_t` and cap it.
- **L21.** A leading or doubled space produces empty arguments, and an empty command matches `continue` (`tools/gsdb.cpp:1039-1043`). **Fix:** split on runs of whitespace and drop empty tokens.

**Variables and expressions**

- **L22.** `variable locals` aborts at the first variable without `DW_AT_location`, such as an `extern` declaration or a `const_value` (`tools/gsdb.cpp:938`). **Fix:** skip those, or print "<optimized out>".
- **L23.** Unchecked optionals:
  - `print_backtrace` dereferences `func_die.name()` (`tools/gsdb.cpp:817`).
  - `handle_variable_read_command` dereferences `data.variable` when the name resolved to functions (`tools/gsdb.cpp:957`).
  - `parse_argument` returns `*res.variable` when it is empty (`src/target.cpp:163`).
  - `find_variable` dereferences a null `elf_file()` (`src/target.cpp:1003`).
  **Fix:** check each one and send an error.
- **L24.** `find_variable` lets the **last** ELF win for global variables, so a library global shadows the executable's (`src/target.cpp:1009-1015`). **Fix:** prefer the executable (stop at the first match).
- **L25.** `parse_argument`:
  - `""` is not accepted as a literal.
  - Commas or parentheses inside string literals break the argument split.
  - `std::isdigit(char)` is UB for negative chars (`src/target.cpp:122-156, 206-216`).
  **Fix:** write a small tokenizer, and cast to `unsigned char` before `isdigit`.
- **L26.** `read_member` cannot see inherited members, throws on static members, and fails for `const S` or typedef'd objects (it doesn't strip) (`src/type.cpp:466-488`). **Fix:** strip cv/typedef, recurse into `DW_TAG_inheritance`, and report static members clearly.
- **L27.** `visualize_class_type` with a `DW_AT_data_bit_offset` field can read past the object, because it reads `byte_size` from the containing byte (`src/type.cpp:56-62`). **Fix:** clamp to `data.size()`.
- **L31.** A piece the compiler optimized out (a `DW_OP_piece` with no location before it) makes the whole variable unreadable. The pieces loop passes the empty location to `read_location_data` (`src/target.cpp:977-978`), which ends at `Invalid location type!` (`src/target.cpp:998`). **✔** A test program reading `%rax` (4 bytes) followed by an empty 4-byte piece got `Invalid location type!`. **Fix:** when `piece.location` holds `empty_result`, leave those bits zero (or flag the value as partly optimized out), advance `offset`, and move on to the next piece.

**Shared libraries and miscellaneous**

- **L28.** `dump_vdso` leaves a `/tmp/gsdb-XXXXXX` directory behind on every launch and ignores `mkdtemp` failure (`src/target.cpp:62-79`). **Fix:** check the return value, and remove the directory in `~target` (or keep the image in memory).
- **L29.** Shared libraries are never unloaded (`src/target.cpp:863-912`), so after `dlclose`/`dlopen` a stale ELF with an old load bias is reused. **Fix:** rebuild the list from the link map and drop missing paths.
- **L30.** `function_name_at_address` returns mangled ELF names (the demangle is commented out) (`src/target.cpp:780-783`). `breakpoint list` prints `No breakpoints set!` without a newline, and never prints it at all because internal breakpoints make the list non-empty (`tools/gsdb.cpp:454-459`). **Fix:** demangle, and filter internal breakpoints before the emptiness check.

## Tests

- **T1.** `test/tests.cpp:698`: the range-list span end is `bytes + range_data.size()` (8 bytes, not 64). The test passes only because `cursor` doesn't bounds-check. **Fix:** multiply by `sizeof(std::uint64_t)`.
- **T2.** `test/tests.cpp:836, 858`: these assert on the old `pc` instead of `new_pc`, so they always pass. **Fix:** use `new_pc`.
- **T3.** `test/tests.cpp:927`: `while (tids.size() < 10)` hangs forever if the target exits early. **Fix:** break when the process exits, then `REQUIRE`.

- **T5.** `test/tests.cpp:881-884`: the loop bound is `frames.size()`, so it reads `expected_names` out of bounds when there are more than 4 frames, and passes vacuously with 0. **Fix:** `REQUIRE(frames.size() == expected_names.size())` first.

Most of C5, H1 and H11 would have been caught. **Fix:** add `[expr]` tests (scalar, small, two-eightbyte and big structs, SSE returns, strings, member calls) and an ASan/UBSan CMake preset in CI.
